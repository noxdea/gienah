Run plugins outside the host process.

Gienah gives Ruby applications a small plugin boundary: child processes, framed RPC, explicit activation, capability checks, and bounded failure.

A narrow contract between code you own and code you load.

Gienah keeps the host’s application model private. Plugins receive protocol messages, not Ruby objects, and every host method can require a declared capability.

Gienah owns the boundary.

  • Manifest discovery and validation
  • Plugin lifecycle and restart policy
  • Framed request, response, and cancellation
  • Capability enforcement and sandbox handoff

Your application owns the product.

  • The host methods plugins may call
  • Activation reasons and contributions
  • Error reporting and user experience
  • Which plugins are installed and trusted

Open the smallest useful door.

Register application-specific methods, discover manifests, and activate a plugin only when its reason occurs.

require "gienah"

host = Gienah::Host.new(api_version: 1)
host.expose("workspace/notify") { |params|
  puts params.fetch("message")
}

host.discover(["plugins"])
plugin = host.activate("example", reason: "onStartup")
plugin&.call("refresh", {}).await(timeout: 2)
